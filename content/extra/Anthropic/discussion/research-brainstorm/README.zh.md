# 研究头脑风暴：思维链是不是真实理由，基准分数高为什么不好用

## 题目

研究头脑风暴（research brainstorm）：面试官给一个开放问题，你边想边说，他顺着你的回答追问；不需要懂模型内部，把模型当黑盒（black box）用过、观察过就够。下面两道题和所有追问都是我们按这种形式补写的，不是原题；每问都写全了背景，可以单独练。

### 第一题：模型写出来的推理，是它的真实理由吗

**Q1.** 面试官说：“现在的模型回答之前会先写一段推理过程，也就是思维链（chain-of-thought，CoT）。这段文字真的是它得出答案的原因吗？假设你只能通过 API 调用模型，看不到权重和激活值，你会怎么研究这个问题？”请用两三分钟讲出你的思路。

**Q2.** 背景同上。面试官追问：“挑一个你最想先做的实验，具体说怎么做：输入是什么，比较什么，你预期看到什么，什么结果会让你改变看法？对照组（control）是什么？”

**Q3.** 背景：你做了一个截断（truncation）实验：让模型先写完整的思维链，然后只保留前一半，让它接着直接给出最终答案。在 1000 道多步推理题上，85% 的题答案和保留完整思维链时一样。同事说：“答案大多没变，说明思维链大多是装饰，模型其实早就想好了。”你同意吗？还要补什么对照或分析？

**Q4.** 面试官问：“为什么做安全的人关心这个问题？假如你的实验发现，在你测的任务上思维链基本是真实的，这个结论能推广到哪里，推广不到哪里？”

### 第二题：基准分数很高，实际却不好用

**Q5.** 面试官说：“一个新模型在某个公开基准（benchmark）上分数很高，比上一代高了很多，但用户反馈说它实际用起来没有明显变好。可能是哪些原因？你先查哪个？”请用两三分钟讲出你的思路。

**Q6.** 背景同上。面试官追问：“你怀疑基准的题混进了训练数据，也就是数据污染（contamination）。你只能调 API，看不到训练数据。最便宜、又能区分不同解释的实验是什么？它有什么局限？”

**Q7.** 背景：你从原基准里随机抽了 500 道题，请人逐题改写：换数字、换说法，考点不变。模型在这 500 道原题上答对 80%，在对应的 500 道改写题上答对 68%。(a) 这 12 个点的差距是不是噪声？算一下。(b) 能不能据此下结论说模型“背过原题”？还缺什么？

**Q8.** 面试官问：“如果让你给团队设计一个不容易被污染、也不容易被刷分的评估，你会怎么做？可以拿你熟悉的领域举例。”

这一轮的证据只有一篇候选人博客（2025 年 2 月，申请的是 Anthropic 的研究 Fellowship）：虚拟现场面里有一场 15 分钟的研究头脑风暴，对方是对齐（alignment）方向的负责人，简短介绍后问了两个开放题，目的是让候选人出主意；作者说这些题不需要 LLM 的内部知识，只要有把模型当黑盒观察的经验和一点创意。作者在第一题上卡住了，沉默了大约三分钟，在脑子里翻自己的数学知识；他事后的总结是当时应该直接出主意。大约一小时后，他的推荐人收到自动通知说不用再谈了；第二天，招聘方取消了剩下的现场面。评分方式没有任何记录，下面关于“强回答”的说法是按研究讨论的一般要求写的，不是 Anthropic 公布的标准。

准备方法：15 分钟两道题，平均每题不到 7.5 分钟，开场回答只能占两三分钟。练一个固定的说话骨架，卡住时也能马上开口：(1) 用一句话把问题变成可以测量的量（“我把‘真实’定义成……”）；(2) 列两三个互相竞争的假设；(3) 挑最便宜、又能区分这些假设的实验，说清楚输入和比较什么；(4) 先说预测：什么结果支持哪个假设，什么结果会让你改变看法；(5) 对照组，排除“任何扰动都会这样”和抽样噪声；(6) 一句局限和下一步。常见的丢分点：长时间沉默；一上来就讲很复杂的方法（尤其是题目说了只能用 API，还去讲看激活值）；只列想法，不说怎么区分；没有对照组；把“看起来合理”当成“真实”；忽略样本量和噪声；结论说得比数据强。可以自然地带上自己的背景，比如计算机视觉里显著图（saliency map）的教训、视频生成里 FID 和 FVD 指标的偏差，下面的答案里有例子。

### 第一题：模型写出来的推理，是它的真实理由吗

**Q1.** 强回答先给定义：思维链“真实”（faithful），是指它写出来的理由就是实际影响答案的因素。这个定义推出两个只用 API 就能检验的后果：

- 如果某个因素改变了答案，思维链应该提到它；
- 如果改动思维链本身，答案应该跟着变，也就是答案依赖思维链。

然后列几个互相竞争的假设：

1. 答案确实依赖思维链，模型是边写边算的；
2. 事后合理化（post-hoc rationalization）：答案先定了，思维链是补上的理由；
3. 看任务：难的多步题依赖思维链，简单题不依赖；
4. 思维链用上了，但漏掉了一部分真实的影响因素（不完整）。

再给两类黑盒实验：

- 改输入，看思维链有没有说出来：在题目里加一个指向某个选项的暗示（hint），看答案有没有被暗示带走，被带走时思维链有没有提到这个暗示。Turpin 等（2023）和 Anthropic 的 Chen 等（2025）用的就是这类做法。
- 改思维链，看答案跟不跟着变：截断、插入一个错误、换个说法重写、换成没有意义的填充字符，然后让模型接着给答案。这是 Lanham 等（2023）的做法。前提是 API 允许你放进一段写好的思维链让模型接着写（预填充，prefill）；不允许的话可以把它放进用户消息里，但那已经不是模型自己写的思维链，要说明这个折扣。

最后挑一个先做（见 Q2），并点出关键区分：思维链“说得通”不等于“真实”。

丢分点：停留在哲学讨论，落不到实验；提议“读一读思维链，看它合不合理”，那测的是合理性，不是真实性；题目说了只能用 API，还去讲看激活值；不提抽样噪声：同一道题重新采样一次，答案本来就可能变。

**Q2.** 一个具体、便宜、能区分假设的实验是暗示注入：

- 数据：几百道有标准答案的选择题。先挑出模型不加暗示时稳定答对的题（例如采样 5 次都对），这样暗示指向错误选项时，答案的变化才好解释。
- 条件：每道题做三个版本。(a) 不加暗示；(b) 加一个指向错误选项的暗示，例如“一位教授认为答案是 (C)”，或者像 Turpin 等那样，把少样本示例的正确答案都排到 (A)；(c) 对照：加一段长度差不多、但不指向任何选项的无关文字。
- 测两个数：翻转率，即答案改成被暗示选项的比例；提及率，即在翻转的题里，思维链把暗示当作理由说出来的比例。“提及”的判断规则要事先定好，可以让另一个模型判，再人工抽查一两百条来校准。
- 预测：如果思维链真实，翻转应该伴随提及；翻转率高而提及率低，就是不真实的证据。
- 什么结果会让我改变看法：暗示组的翻转率和对照组差不多，说明暗示根本不起作用，这个实验测不出东西，要换更强的暗示；或者提及率接近 100%，说明至少对这类暗示，思维链是如实的。
- 对照：(1) 不加暗示的版本重新采样一次，得到“答案本来就会变多少”的基线；(2) 无关文字组，排除“任何扰动都会让答案变”；(3) 暗示指向正确答案的版本，看暗示的作用是不是双向的；这一组要换成模型原本答得不稳的题，在稳定答对的题上答案已经是正确选项，看不出变化。

已有结果可以顺口提一句，但要说准：Turpin 等（2023）在输入里加偏置特征（例如把少样本示例的选项重新排序，让答案总是 (A)），模型的解释系统性地不提这些特征；把模型往错误答案上引时，它常常写出为错误答案辩护的思维链，在 13 个 BIG-Bench Hard 任务上准确率最多下降 36%（测的是 GPT-3.5 和 Claude 1.0）。Chen 等（2025）测了 6 种暗示：在大多数设置和模型上，模型用了暗示时，思维链说出来的比例至少有 1%，但常常低于 20%。

丢分点：没有对照组；只报翻转率、不报提及率（翻转只说明暗示有影响，不说明思维链不真实）；暗示加在模型本来就不会的题上，答案的变化无法解释；“提及”的判断规则事后才定。

**Q3.** 不能直接同意。85% 不变至少有三种解释，要分开看：

1. 很多题根本不需要思维链。假设 1000 道题里有 60% 不写思维链、直接回答也是同一个答案，这部分截断后自然不变。那么剩下 40% 的题里答案不变的比例 $x$ 满足 $0.6 + 0.4x = 0.85$，得 $x = 0.625$：这些题里有 37.5% 的答案被截断改变了，依赖程度其实不低。所以要先跑一遍“完全不写思维链”，按结果把题分成两层，再看截断的影响。
2. 抽样噪声。同一道题、保留完整思维链重新采样两次，答案一致的比例也不是 100%，这个比例才是天花板。如果它只有 90%，截断后的 85% 离天花板只差 5 个点；如果它是 99%，差距就是 14 个点。这个重采样对照必须有。
3. 截一半只是一个点。应该画一条曲线：保留 0%、25%、50%、75%、100% 的思维链时，答案和完整版一致的比例怎么变。Lanham 等（2023）发现，这种依赖在不同任务之间差别很大，有的任务很依赖思维链，有的基本不看。

还有一个概念上的区分值得说：答案不依赖后半段思维链，不等于思维链“是装饰”。模型可能在前半段就真的算出了答案，后半段只是复核；这时后半段不必要，但整段思维链仍可能如实反映了它的过程。“必要”和“真实”是两个问题，截断实验测的主要是前者。

丢分点：直接接受同事的结论；只说“不能下结论”，不给下一步分析；没想到题目的难度构成会影响这个比例。

**Q4.** 为什么在意：如果模型的推理写在思维链里而且是真实的，我们就可以读它、用另一个模型监控它（CoT monitoring），在模型真正行动之前发现它在钻奖励的空子（reward hacking）、在骗人或者在计划有害的事。思维链不真实，这种监控就会被骗过。Chen 等（2025）的结论是：监控思维链是在训练和评估中发现不良行为的一个有希望的办法，但不足以排除这些行为；在他们那种思维链并非必要的设置下，靠测试时监控思维链不太可能可靠地抓到罕见而严重的意外行为。他们还发现，基于结果的强化学习一开始能提高真实性，之后进入平台期，不会饱和。

结论推广不到哪里，强回答至少说出三四点：

- 任务：在这几类任务上真实，不代表在别的任务上也真实。Lanham 等发现任务之间差别很大。
- 暗示的种类：你只测了你想到的那几种暗示。模型可能会说出“教授说是 C”，却不说出它觉得不该用的信息（例如偷看到的评分标准）。
- 是否需要思维链：模型不写思维链也能做的事，它没有理由把真实过程写下来，而最需要监控的恰恰可能是这一类。
- 优化压力：如果训练时惩罚思维链里的“坏念头”，模型可能学会不写出来，而不是不去做，可监控性会变差。
- 模型规模和版本：Lanham 等发现，在他们研究的大多数任务上，模型越大、能力越强，推理越不真实。换了新模型要重测。
- 形式：从选择题换到长时间运行的智能体（agent）任务，思维链的作用可能完全不同。

可以带上自己的背景：计算机视觉里的显著图有过同样的教训。Adebayo 等（2018）发现，有些显著图方法的结果既不依赖模型，也不依赖数据，作者把它比作边缘检测；他们的检验办法之一就是把模型权重随机化，看解释变不变。教训和这里一样：解释“看起来合理”不够，要用干预去测它是不是随真正的原因变化。

丢分点：只说“为了安全”，说不出具体用途；把一次实验的结论说成普遍成立。

### 第二题：基准分数很高，实际却不好用

**Q5.** 先反问一句“不好用”具体指什么：哪类任务、哪些用户、和哪个版本比、有没有例子。然后把可能的原因摆出来：

1. 数据污染：基准的题，或者很像的题，进了训练数据，模型是记住了而不是学会了。
2. 分布不一样：基准的题短、干净、单轮，用户的请求长、乱、多轮，还要用工具。
3. 学会了格式上的捷径：例如对选项位置的偏好，或者专门针对评测的提示词调过。
4. 指标测的不是用户在意的东西：只看最终答案对不对，不看过程和表达。可以用自己熟悉的例子：视频生成常用的 FVD 偏向单帧画质，Ge 等（2024）发现，在时间维度上大幅破坏视频，FVD 只升高一点；图像上，Kynkäänniemi 等（2022）发现，只要让生成图的 ImageNet Top-N 分类结果的分布和真实图对齐，就能大幅降低 FID，而画质并没有变好。
5. 评测设置和上线设置不一样：少样本示例、思维链、温度、多次采样取最好、系统提示词、工具。
6. 反馈本身有偏：抱怨集中在少数场景；或者新模型在别的方面退步了（风格、拒答、延迟），用户把它算成“不好用”。
7. 基准接近饱和，几个点的差距本身就在噪声里。

先查哪个：先查最便宜、又最常见的。用上线时的配置（同样的提示词、温度、不加少样本示例）在基准上重跑一遍，看分数还在不在；同时随机抽 100 条用户反馈逐条归类，看问题到底出在哪类任务上。之后再做污染检验（Q6）。

丢分点：一上来就断定是污染；不问“不好用”指什么；列了一长串原因，却不说先查哪个、为什么。

**Q6.** 最便宜的是两个只用 API 的检验，一起做：

- 续写检验（completion test）：给模型基准题目的前一半，让它续写，统计续写和原文逐字或几乎逐字重合的比例。对照组是一批风格相同、但在模型训练数据截止日期之后才写出来的题。基准题的重合率明显高于对照组，说明模型见过原文。如果 API 返回每个词元（token）的对数概率，还可以比较原题和改写题的似然。
- 扰动检验：考点不变，只换数字、人名或者选项顺序。真学会了，分数应该基本不变；靠记忆，分数会掉。GSM-Symbolic（Mirzadeh 等，2024）发现，只改题目里的数值，所有被测模型的表现都会下降，同一道题的不同实例之间分数差别也很明显。

一个现成的参照是 GSM1k（Zhang 等，2024）：仿照 GSM8k 的风格和难度新写了一套题，有的模型准确率最多掉 8%，有几个模型家族在几乎所有规模上都有系统性过拟合；模型生成 GSM8k 原题的概率和它在两个基准上的分差正相关（Spearman $r^2 = 0.36$）。但很多模型，尤其是前沿模型，几乎没有过拟合的迹象。

局限：续写检验只能发现逐字记忆，抓不到“训练数据里有改写过的版本”这种污染，模型可能记住了答案却背不出原文；对照题的难度必须和原题相当，否则比较不公平；聊天模型可能不愿意逐字续写，结果偏低；查不出来不能证明没有污染。

丢分点：说要去查训练数据（题目说了看不到）；只做一种检验；没有对照组。

**Q7.** (a) 先算单个比例的标准误：

- 原题：$\sqrt{0.8 \times 0.2 / 500} \approx 1.79$ 个点；
- 改写题：$\sqrt{0.68 \times 0.32 / 500} \approx 2.09$ 个点。

如果把两组当成独立样本，差的标准误是 $\sqrt{1.79^2 + 2.09^2} \approx 2.75$ 个点，12 个点约是 4.4 倍标准误，不是噪声。

但这里每道改写题都对应一道原题，是配对数据，更好的做法是逐题比较（McNemar 检验）。假设逐题看，原题对、改写题错的有 85 道，原题错、改写题对的有 25 道，这和 80%、68% 是一致的：$(85-25)/500 = 12\%$。配对差的标准误是 $\sqrt{85 + 25 - (85-25)^2/500}\,/\,500 \approx 2.03$ 个点，比按独立样本算的小，因为同一道题的原题和改写题难度相关。McNemar 统计量是 $(85-25)^2/(85+25) \approx 32.7$，p 值远小于 0.001。

(b) 不能。差距是真的，但“背过原题”只是一种解释，另一种同样常见的解释是改写题本身更难。Recht 等（2019）照着原来的流程重新收集了 CIFAR-10 和 ImageNet 的测试集，各种模型的准确率分别掉了 3%–15% 和 11%–14%；作者的结论是，下降不是因为大家在旧测试集上反复调参，而是新图片稍微“更难”。

还缺一个参照：拿几个不可能见过这个基准的模型（例如在基准发布之前就训练完的模型），在同样的原题和改写题上测，看它们掉了多少。如果参照模型也掉 10 个点左右，主要是改写题更难；如果它们只掉两三个点，我们的模型多掉的那部分才可疑。这就是双重差分（difference-in-differences）的思路。另外可以请人盲评两组题的难度，再看下降是不是集中在 Q6 续写检验里能背出原文的那些题上。

丢分点：只看 12 个点就下结论；忘了这是配对数据；把“差异显著”当成“原因已知”。

**Q8.** 强回答从两个目标出发：难被污染、难被刷分；同时和用户真正在意的东西相关。可以说的做法：

- 保留一份不公开的测试集，只在少数关键决定时使用，定期换新。用得越多，越容易在它上面过拟合，所以也要限制查看的次数。
- 按出题日期切分，只用训练数据截止日期之后写的题，比较新旧两部分的分差。
- 用模板或程序生成题目（GSM-Symbolic 的思路），每次评测都抽新的实例，同时报告不同实例之间的波动。
- 公开发布的评测数据里加金丝雀字符串（canary string），方便训练流程把它过滤掉；训练数据一侧做 n-gram 重合检查。
- 每个分数都报置信区间；比较新旧模型时用配对比较，跑多个随机种子。
- 定期检查评测分数和真实使用结果是否一致：在几个模型版本上，评测分数的排序和用户偏好、任务完成率的排序是否相同；不一致，说明这个评测已经不在测你想测的东西。
- 拿视频生成举例：不要只看 FVD，补上专门针对运动和时间一致性的指标和人工评分；并且主动检查指标能不能被不提升质量的手段刷低，就像前面提到的 FID 和 ImageNet 类别分布的问题。

丢分点：只说“换一个更大的基准”；以为不公开的测试集就不会过拟合；只讲防污染，不讲评测要和真实使用相关。

se_orig = math.sqrt(0.8 * 0.2 / n) * 100
se_new = math.sqrt(0.68 * 0.32 / n) * 100
se_diff = math.hypot(se_orig, se_new)          # independent samples
assert round(se_orig, 2) == 1.79
assert round(se_new, 2) == 2.09
assert round(se_diff, 2) == 2.75
assert round(12 / se_diff, 1) == 4.4

# paired counts must agree with 80% and 68%
b, c = 85, 25          # original right & rewrite wrong, original wrong & rewrite right

both_right = orig_right - b
rewrite_right = both_right + c

neither = n - both_right - b - c

assert round(chi2, 1) == 32.7

assert abs(diffs.mean() - 12) < 0.05
