# OpenAI: which problems are included, and why

**In short: all 63 topics come from the OpenAI interview notes compiled by Schuture; none was removed and none was added.** Every page was re-checked; see the [audit report](#/audit) for what was changed.

## What is included

| Category | Count | Notes |
| --- | ---: | --- |
| Coding | 38 | About ten of them are ML and math problems (NumPy, backpropagation, finding bugs in a Transformer, and so on) |
| System design | 21 | Product and infrastructure systems, plus a few AI systems (inference serving, video generation, retrieval, agent evaluation, and more) |
| Behavioral and culture | 4 | Coordinator screen, hiring manager round, technical deep dive, engineering management; each page is split into one card per question |

The notes' own index page says "37 coding, 22 system design", one off from the 38 and 21 actually in the folders; its index was simply not updated, and no problem is missing.

## Why nothing was added

Problems are added in only one situation: the interview reports mention a type of problem but leave no concrete problem of that type.

Every type of round listed in OpenAI's [interview process](#/openai/process) (coding, ML coding, system design, technical deep dive, behavioral, and hiring manager) already has concrete problems in the notes; there are no gaps where only the name of a problem type is left, so there are no added problems here.

## What is not included

None of the other materials at hand (assorted generic ML exercises, mock assessment question banks) are OpenAI interview reports, so none of them were included here. If you want more practice on generic problems, a coding-practice site is a better place; putting them here would only bury the real interview problems.

## Things to keep in mind

- **The problems are write-ups, not originals.** The notes' author rewrote the problem statements and added reference solutions based on multiple interview reports. What you meet in the interview will be the same type of problem, with different details.
- **The "Frequency" column is the notes author's own count**, indicating how often the problem appeared in the interview reports he saw; we have no way to verify it independently. If you are short on time, do the high-frequency problems first.
- **The official interview guide could not be checked.** OpenAI's official page could not be opened this time (the server refused access), so the "can you use AI" rules are based on candidate reports; see [AI rules and interview environment](#/openai/rules) for details.
